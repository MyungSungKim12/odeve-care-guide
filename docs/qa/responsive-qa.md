## 화면 크기별 결과

| 화면 | 확인 페이지 | 결과 |
| --- | --- | --- |
| 320×568 | 홈 | 3개+2개 메뉴가 첫 화면 안에 표시, 가로 스크롤 없음 |
| 360×800 | 입술 상세 | 탭 가로 스크롤, 원본 이미지 비율 유지, 가로 스크롤 없음 |
| 390×844 | 홈 | 3개+2개 메뉴가 첫 화면 안에 표시, 전체 터치 영역 정상 |
| 430×932 | 입술 상세 | 탭 전환, 안내 이미지 및 확대 버튼 정상 |
| 768×1024 | 홈 | 간결한 3개+2개 메뉴, 영문명 잘림 없음 |
| 1024×1366 | 입술 회복 과정 | 좌측 탐색·우측 세로 이미지 배치 정상 |
| 1280×800 | 홈 | 설명형 3개+2개 카드가 첫 화면 안에 표시 |

홈 화면은 320×568, 390×844, 768×1024, 1024×1366, 1280×800에서 모두 정확히 두 줄로 배치되고 마지막 메뉴가 초기 화면 높이 안에 들어오는 것을 확인했다. 모든 측정 화면에서 `documentElement.scrollWidth`와 `clientWidth`가 같아 페이지 수준의 가로 넘침이 없었다. 이미지 확대 화면은 430×932에서 열기와 닫기를 확인했으며, 닫힌 뒤 dialog 요소가 0개로 복구되었다.

## 기기 대응 기준

화면은 특정 기기 이름이나 해상도에 고정하지 않고 CSS Grid, `clamp()`, 최대 콘텐츠 너비, 안전영역 환경 변수를 사용한다. 따라서 iPhone, Android 스마트폰, 폴더블, iPad, Galaxy Tab의 중간 너비에서도 콘텐츠가 사용 가능한 공간에 맞춰 유동적으로 재배치된다.
